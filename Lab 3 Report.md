# Обычная лабораторная, первая часть: 
Написать “плохой” CI/CD файл, который работает, но в нем есть не менее трех “bad practices” по написанию CI/CD
Написать “хороший” CI/CD, в котором эти плохие практики исправлены
В Readme описать каждую из плохих практик в плохом файле, почему она плохая и как в хорошем она была исправлена, как исправление повлияло на результат


Я добавил линтер(ы), чтобы код test_taskly.py не был совсем пустышкой. 
Из-за указания на последнюю версию python, гитхаб не может собрать проект. Моя bad practice ломает код, а так быть не должно. 
Я изменил код add_task (неточное название) так, чтобы тесты, которые я включу в good-ci на main ветке не проходили. Это и есть разница между плохим и хорошим файлом.
